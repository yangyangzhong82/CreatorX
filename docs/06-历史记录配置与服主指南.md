# 第 6 章：历史记录、配置与服主指南

本章面向服主、管理员与重度建筑师，详解 CreatorX 的**历史恢复与磁盘溢写机制**、**分 tick 防卡服调度**、**`config.jsonc` 全部配置项**与**常见问题排查**。

---

## 6.1 历史记录（撤销 / 重做 / 跨玩家回滚）

所有改动世界的操作（填充、替换、四壁、外壳、掏空、表层、中心、移动、堆叠、形状生成、剪切、粘贴）都会完整记录原方块、含水第二层、方块实体 NBT 以及被移除/新生成的实体。

| 命令 | 短命令 | 语法 | 功能说明 |
| --- | --- | --- | --- |
| **撤销操作** | `/cx undo` | `/cx undo [步数] [玩家名或UUID]` | 逆序恢复最近 `[步数]` 次操作（默认 `1` 次）。填写 `[玩家名或UUID]` 时，管理员可直接帮其他在线或离线玩家回滚误操作！ |
| **重做操作** | `/cx redo` | `/cx redo [步数] [玩家名或UUID]` | 重新应用最近被撤销的 `[步数]` 次操作（默认 `1` 次），同样支持指定其他玩家 |
| **查看历史列表** | `/cx history` | `/cx history` | 列出当前所有可撤销与可重做记录的操作类型、涉及方块数及精确执行时间 |
| **清空历史栈** | `/cx clearhistory` | `/cx clearhistory` | 清空自己的撤销与重做记录 |
| **中止运行任务** | `/cx cancel` | `/cx cancel` | 立即停止你当前正在后台执行的编辑、复制、粘贴、统计或撤销任务 |
| **热重载配置** | `/cx reload` | `/cx reload` | 不重启游戏重新加载 `config.jsonc`、语言文件、黑名单与可视化选项 |

### 历史持久化与内存溢写（为什么重进服还能撤销？）
与传统只把历史放内存、一退服就全丢的工具不同，CreatorX 拥有完善的磁盘级保护：
1. **自动内存溢写（Disk Spill）**：每位玩家在内存中默认最多驻留 `5,000,000` 个历史方块（`history.maxBlocksInMemory`）。一旦超出阈值，后台写入线程会自动把较旧的历史记录序列化到 `mods/creatorx/data/history-cache/` 磁盘缓存中并释放内存；等你执行 `/cx undo` 用到它时再按需读回。
2. **退出游戏与重启服务器不丢失**：玩家的**历史记录索引、剪贴板、最近 10 条图案/掩码、魔杖开关与线框开关**都会按存档独立保存在 `mods/creatorx/data/players/<世界ID>/<UUID>.nbt` 中。下次上线依然可以撤销上次退出前盖错的建筑！模组启动时还会自动清理不再被任何玩家引用的孤立历史缓存文件。
3. **中途取消安全可逆**：当百万级大填充运行到一半被你用 `/cx cancel` 喊停（或玩家突然掉线自动中止）时，**已经写入世界的那一半方块依然会生成一条合法的历史记录**，紧接着敲一次 `/cx undo` 就能干干净净全部撤回！如果取消的是正在进行的撤销/重做任务，已写回的部分会进入对侧栈，未写回的部分留在原栈，一格都不会乱。

## 6.2 分 Tick 异步调度与服务器保护

为什么用 CreatorX 填充几百万方块不会把服务器卡崩掉线？

1. **双预算分片调度**：
   - 全服所有正在运行的任务共享每 tick 的**方块数量上限**（`performance.blocksPerTick`，默认 `20,000`）与**时间上限**（`performance.tickBudgetMs`，默认 `15.0` 毫秒）。
   - 多人同时执行大任务时，调度器会自动将预算均分给每个活动任务（每位玩家同时最多运行 `1` 个任务，全服并发上限 `performance.maxConcurrentJobs` 默认 `4` 个）。任一预算耗尽立即让出主线程，绝不拖垮服务器 TPS。
2. **区块局部性遍历与自动加载**：
   - 区域遍历采用 **`区块列 → Y → Z → X`** 顺序（围墙模式还会直接跳过内部空区块），让同一区块的读写高度集中。
   - 遇到远处尚未加载的区块时，任务会自动创建临时区块加载视图等待区块就绪（最长等待 `30` 秒；若超出世界边界或超时则安全中止并保留已完成部分供撤销）。
3. **物理更新抑制（`performance.physics: false` 默认关闭）**：
   - 默认写入方块时**只同步客户端画面，不触发邻居物理更新**。这样你在空中批量放置沙子、砾石、水、岩浆或红石机械时，沙子不会哗啦啦全掉下来，水也不会四处漫溢引发连锁卡顿。如果你确实需要触发原版方块更新，可在配置中将 `physics` 设为 `true`。
4. **三级防误操作防线**：
   - **选区体积上限**（默认 `8,000,000` 格）：设点或扩选超出直接拦截。
   - **单次改动上限**（默认 `4,000,000` 格）：单次任务涉及改动超限直接拒绝执行。
   - **大操作弹窗确认**（默认超过 `1,000,000` 格触发）：自动弹出二次确认对话框，点「执行」后才真正动工。

## 6.3 配置文件详解（`config.jsonc`）

配置文件位于 `mods/creatorx/config/config.jsonc`，支持 `//` 与 `/* */` 注释。版本升级新增顶层配置项时，模组会自动补齐缺失项并保留你原有的注释。修改后在游戏内执行 **`/cx reload`**（或在主菜单「设置 → 重新加载配置」点击）即可立即生效（*唯独 `command.shortCommands` 涉及命令树注册，修改后需重启服务端/客户端生效*）。

```jsonc
{
    // 配置格式版本，保持为 1 即可。
    "version": 1,

    // 控制台日志级别：Off、Fatal、Error、Warn、Info、Debug、Trace。
    "logLevel": "Info",

    // 界面与提示语言，对应 lang/ 目录下的文件名（内置 zh_CN 简体中文、en_US 英文）。
    "language": "zh_CN",

    "command": {
        // 是否同时注册 /pos1、/set、/copy、/undo 等省略 /cx 的短命令（修改此项需重启生效）。
        "shortCommands": true
    },

    "limits": {
        // 单个长方体选区允许包含的最大方块体积（含两个角点）。
        "maxSelectionVolume": 8000000,
        // 单次操作最多允许改动的方块数，超过时直接拒绝执行。
        "maxChangesPerOperation": 4000000,
        // 预计改动超过此方块数时，先弹出二次确认窗口。
        "confirmThreshold": 1000000,
        // 禁止通过图案放置的方块列表（粘贴与堆叠时遇到它们会自动跳过）。
        "disallowedBlocks": [
            "minecraft:command_block",
            "minecraft:chain_command_block",
            "minecraft:repeating_command_block",
            "minecraft:structure_block",
            "minecraft:barrier"
        ]
    },

    "performance": {
        // 全服所有任务每 tick 合计最多写入的方块数（读取预算按 4:1 折算）。
        "blocksPerTick": 20000,
        // 全服所有任务每 tick 合计最多占用的主线程毫秒数（范围 0.1 ~ 100.0）。
        "tickBudgetMs": 15.0,
        // 全服同时运行的任务数上限（每位玩家同一时间最多 1 个任务）。
        "maxConcurrentJobs": 4,
        // true：写方块时通知邻居（触发落沙、水流扩散、红石更新）；false：仅同步客户端，性能最佳。
        "physics": false
    },

    "history": {
        // 每位玩家最多保留的可撤销步数。
        "size": 30,
        // 每位玩家在内存中驻留的历史方块数上限，超出部分自动异步溢写到硬盘缓存。
        "maxBlocksInMemory": 5000000
    },

    "selection": {
        // /cx hpos1 与 /cx hpos2 准星射线检测的最远距离（1.0 ~ 512.0 格）。
        "traceDistance": 128.0
    },

    "wand": {
        // /cx wand 发放的选区魔杖物品完整 ID。
        "item": "minecraft:wooden_axe",
        // true：仅 /cx wand 领取的带专属标记魔杖可设点；false：任何同款物品（如普通木斧）都能设点。
        "requireTag": true,
        // true：手持魔杖潜行（蹲下）右键直接打开 CreatorX 主菜单。
        "sneakOpensMenu": true
    },

    "visual": {
        // 选区边框渲染模式：
        // "auto"      - 装了 CreatorX 的增强客户端显示实线框，其余原版客户端显示粒子；
        // "shapes"    - 强制下发线框包；
        // "particles" - 强制使用粒子显示边框；
        // "none"      - 全局关闭选区边框。
        "mode": "auto",
        // 选区边框最大渲染距离（0 ~ 512.0 格）。
        "maxDistance": 128.0,
        // 粒子模式下使用的粒子 ID。
        "particle": "minecraft:villager_happy",
        // 粘贴预览（-p）体积不超过该值时发送真实外观假方块；超过该值时仅显示落点边界绿框（0 ~ 32768）。
        "previewMaxBlocks": 4096,
        // 粘贴预览持续有效秒数，超时未确认自动恢复原状（5 ~ 120 秒）。
        "previewSeconds": 30
    },

    "client": {
        // （仅客户端有效）是否启用屏幕下方动作栏 CreatorX 状态 HUD。
        "hud": true,
        // （仅客户端有效）进入未安装 CreatorX 的远程服务器时，是否在动作栏显示本地脚下坐标。
        "localCoordinates": true
    }
}
```

## 6.4 常见问题与故障排查（FAQ）

### Q1：为什么我拿木斧敲方块没设点，直接把方块敲碎了？
1. **检查权限**：确认你拥有 OP（操作员 / `GameDirectors`）权限。
2. **检查魔杖来源**：`wand.requireTag` 默认为 `true`，你自己从创造背包拿出来或工作台合成的普通木斧不会触发设点——请执行 **`/cx wand`** 领取专属魔杖。
3. **检查魔杖开关**：看是否之前点过停用魔杖；输入 `/cx togglewand` 或在菜单「设置」中确认魔杖处于 **「已启用」** 状态。

### Q2：设好了点 1 和点 2，为什么看不见绿色选区边框？
1. 确认点 1 和点 2 是在**同一个维度**设置的。
2. 打开 `/cx menu` → **「设置」**，确认「选区线框」显示为 **「显示」**，且 `config.jsonc` 中 `visual.mode` 不是 `"none"`。
3. 如果你没有装客户端模组且关掉了游戏视频设置里的「粒子效果」，粒子边框也会被原版隐藏；开启游戏粒子显示或安装客户端版 CreatorX 即可看到清晰实线框。

### Q3：提示「此操作预计改动 X 个方块，超过单次 Y 个的上限」怎么办？
这是防止超大选区卡服的保护阈值。你可以：
- 把选区分两次处理，或如果是做空心建筑改用 `/cx walls`、`/cx faces`；
- 服主也可以打开 `mods/creatorx/config/config.jsonc`，适当调大 `limits.maxSelectionVolume` 和 `limits.maxChangesPerOperation`，然后执行 `/cx reload` 立即生效。

### Q4：为什么输入 `/set` 提示未知命令或变成别的插件命令了？
1. 检查 `config.jsonc` 中的 `command.shortCommands` 是否为 `true`（改完需重启服务器）。
2. 如果服务器上其他插件也占用了同名短命令，请始终使用带前缀的 **`/cx set`**，`/cx` 主命令永远不会冲突且全部功能一致。

### Q5：低配服务器觉得大任务执行时有点掉帧，怎么调优？
打开 `config.jsonc`，将 `performance.blocksPerTick` 从 `20000` 下调至 `8000`，将 `performance.tickBudgetMs` 从 `15.0` 下调至 `8.0`，然后执行 `/cx reload`。任务每个 tick 占用的时间减半，服务器会极其丝滑。
