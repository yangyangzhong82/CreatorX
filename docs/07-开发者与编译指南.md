# 第 7 章：开发者与编译指南

本章面向希望参与 CreatorX 开发、阅读源码或自行编译服务端 / 客户端构建包的开发者，梳理项目的**模块分层、核心执行链路、数据存储格式**与 **Xmake 构建方法**。

---

## 7.1 技术栈与构建基线

- **编程语言**：C++20（Windows 平台使用 `clang-cl` 工具链，LLVM 22，禁用 C++ 异常冲突配置 `/EHa` + `/utf-8`）
- **构建系统**：[Xmake](https://xmake.io/) + `@levibuildscript`
- **加载器依赖**：`levilamina 26.60.8`（`tooth.json` 兼容声明为 `26.60.*`，对应 Minecraft 基岩版 / BDS `1.26.60`）
- **单仓库双目标**：同一套 `src/` 源码通过编译宏切换构建目标：
  - `--target_type=server`：定义 `LL_PLAT_S`，产出专用服务端插件。
  - `--target_type=client`：定义 `LL_PLAT_C`，产出客户端插件（同时包含单人/局域网内置服务端完整逻辑，以及客户端快捷键、资源包与动作栏 HUD）。

## 7.2 源码目录结构

```text
CreatorX/
├─ xmake.lua                  # Xmake 构建脚本（支持 server / client 双目标）
├─ tooth.json                 # lip 包管理器发布清单（含默认服务端与 #client 变体）
├─ manifest.json              # LeviLamina 模组元数据模板
├─ config.jsonc               # 默认带注释配置文件（首次启动复制到模组配置目录）
├─ lang/                      # 多语言词条（zh_CN.json / en_US.json）
├─ resource_packs/            # 客户端快捷键本地化资源包（creatorx_shortcuts）
└─ src/
   ├─ mod/                    # 模组生命周期入口（Entry.cpp：load / enable / disable / unload）
   ├─ Config/                 # 基于编译期反射的 JSONC 配置读写与保留注释自动补全
   ├─ I18n/                   # 国际化文本加载与 tr() 格式化接口
   ├─ core/                   # 与 MC 解耦的纯数学与几何结构
   │  ├─ math/Vec3i.h         # 三维整数坐标与六个基本朝向枚举
   │  └─ region/              # Box 包围盒、按区块列局部性遍历的 BoxIterator、CuboidSelection
   ├─ session/                # 玩家会话管理（选区、剪贴板、历史栈、最近 10 条图案/掩码、NBT 持久化）
   ├─ edit/                   # 编辑核心引擎
   │  ├─ Pattern.*            # 图案（权重随机 / 方块状态 / 手持方块 / 编辑距离纠错）与掩码解析器
   │  ├─ Clipboard.*          # 剪贴板存储、双层方块/方块实体/生物实体拷贝、90° 三维旋转与镜像状态变换
   │  ├─ ChangeSet.*          # 调色板压缩历史变更集、方块/实体双向回放、后台异步磁盘溢写（Spill）
   │  └─ Jobs.*               # 各类分片任务实现（填充/生成/统计/搬运堆叠/复制剪切/粘贴/撤销重做）+ ChunkAccess
   ├─ exec/                   # 分 tick 预算调度器（JobScheduler：均分方块数与毫秒预算、动作栏 ETA 进度）
   ├─ schematic/              # .cxs 与原版 .mcstructure 结构序列化/反序列化及路径安全校验
   ├─ storage/                # 独立后台单线程 NBT 队列原子写入器（.tmp + MoveFileExW 替换）
   ├─ visual/                 # 服务端可视化（SelectionOutline 线框/粒子切换、PastePreview 假方块预览）
   ├─ net/                    # 双端可选增强协议（StatusPacket：creatorx:status 实时同步 HUD）
   ├─ input/                  # 客户端键盘快捷键注册（KeyRegistry，仅 LL_PLAT_C 编译）
   ├─ ui/                     # 图形化表单菜单（Menu.cpp 基础菜单 + AdvancedMenu.cpp 形状/变换/原理图表单）
   └─ command/                # 命令注册与参数解析（SelectionCommands / EditCommands / AdvancedCommands）
```

## 7.3 核心架构设计亮点

### 1. 一次操作是如何安全落地的？
1. **交互入口（`command/` 或 `ui/`）**：校验玩家 `GameDirectors` 权限 → 解析 `Pattern` / `Mask` 或几何参数 → 构造对应的 `exec::Job` 子类实例。
2. **安全门禁（`startJob`）**：检查玩家是否已有运行中任务、全服并发是否超限、预计改动是否超过 `maxChangesPerOperation`；若超过 `confirmThreshold` 或带 `-p` 粘贴预览，先挂起 `Job` 并发送 `ModalForm` 弹窗等待玩家确认（通过 `generation` 与维度校验防止重载或跨维度后失效回调）。
3. **分片执行（`exec::JobScheduler` + `edit::ChunkAccess`）**：每个服务端 Tick 按在线运行任务数均分 `blocksPerTick` 和 `tickBudgetMs`。`BoxIterator` 按 **`区块列 → Y → Z → X`** 步进；若目标区块未加载，`ChunkAccess` 通过玩家创建临时 `ChunkViewSource` 异步加载（30 秒超时保护）。
4. **调色板变更记录（`edit::ChangeSet`）**：每次调用 `writeBlock()` 时，自动读取旧方块、含水第二层（`getExtraBlock`）与旧方块实体 NBT，去重存入 `Pool` 调色板并以紧凑整数下标记录，同时自动修正双格大箱子的 `pairx` / `pairz` 坐标。任务结束（哪怕中途被 `/cx cancel` 取消）统一压入 `History` 撤销栈。

### 2. 原子级异步存储与磁盘溢写（`storage/` + `ChangeSet`）
- **世界对象绝不跨线程**：所有 `BlockSource` / `Actor` 读写严格限制在服务端主线程；跨入后台 `storage::Writer` 线程的只有值拷贝好的 `CompoundTag`。
- **防损坏原子替换**：`storage::writeNbt` 先将二进制 NBT 写入 `<目标文件>.tmp`，落盘成功后再调用 `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` 原子替换原文件，掉电或崩服也不会产生半截损坏文件。
- **数据目录布局（位于 `mods/creatorx/data/`）**：
  ```text
  data/
  ├─ schematics/                        # 用户保存的 .cxs 与 .mcstructure 原理图
  ├─ history-cache/                     # 超出内存上限后溢写落盘的 ChangeSet (<timestamp>-<seq>.nbt)
  └─ players/<levelIdHex>/
     ├─ <uuid>.nbt                      # 玩家历史引用栈、魔杖/线框开关、最近图案与掩码
     └─ <uuid>.clipboard.nbt            # 玩家持久化的剪贴板内容
  ```

### 3. 双端自适应网络协议（`net/Enhancements.cpp`）
- 使用 LeviLamina 的 `PacketRegistrar` 注册 `Optional = true` 的自定义包 `creatorx:status`。
- 服务端通过 `StatusPacket::canSendTo(player)` 自动识别该玩家是否为安装了 CreatorX 的增强客户端：
  - **增强客户端**：启用 `PrimitiveShapesPacket` 线框渲染（`auto` 模式下）并每秒推送动作栏 HUD 状态包。
  - **普通原版客户端**：无需装任何客户端插件也能正常进服，选区自动无缝降级为粒子边框。

## 7.4 本地编译指南

### 1. 环境准备
1. **Windows 10 / 11 x64**
2. **Visual Studio 2022**（勾选「使用 C++ 的桌面开发」以提供 Windows SDK 与 MSVC 标准库头文件）
3. **LLVM / Clang 22**（确保 `clang-cl` 在系统 `PATH` 中，与 CI 环境一致）
4. **Xmake**（最新版）

### 2. 编译专用服务端版本（Server）

在仓库根目录打开终端执行：

```powershell
# 更新 LeviMC 官方仓库索引
xmake repo -u

# 配置为 Windows x64 Release 服务端目标
xmake f -p windows -a x64 -m release --toolchain=clang-cl --target_type=server -y

# 开始编译并打包
xmake -y
```

编译完成后，产物位于 `bin/creatorx/` 目录（已自动附带 `config.jsonc` 与 `lang/` 文件夹），直接将其复制到 BDS 的 `mods/creatorx/` 即可测试。

### 3. 编译客户端版本（Client）

```powershell
# 切换配置为客户端目标
xmake f -p windows -a x64 -m release --toolchain=clang-cl --target_type=client -y

# 开始编译并打包
xmake -y
```

客户端构建除了生成 `creatorx.dll`、`config.jsonc` 和 `lang/` 外，`after_build` 脚本还会自动把 `resource_packs/creatorx_shortcuts` 复制进 `bin/creatorx/resource_packs/`。

## 7.5 扩展新功能的常见步骤

1. **新增配置项**：在 `src/Config/Config.h` 对应结构体中添加字段与默认值（若新增嵌套结构体需特化 `is_reflectable<T>`），并在 `src/Config/ConfigManager.cpp` 的 `normalizeConfig()` 中补充边界钳制，最后同步更新根目录 `config.jsonc` 注释。
2. **新增多语言文本**：在 `lang/zh_CN.json` 与 `lang/en_US.json` 中同步添加键值，代码内统一调用 `tr("key", args...)`。
3. **新增编辑任务**：继承 `exec::Job` 实现 `total()`、`progress()`、`run(Level&, Budget const&)` 与 `finish(Player*, JobEnd)`，在 `command/` 注册命令并在 `ui/` 中挂载表单入口。
